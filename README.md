# 智研司 · AI Company

本机优先的中文 AI 研发协作管理台：管理员工、项目、任务、技能草稿与人工审批，探索“负责人规划 → 开发 → 独立 QA → 人类批准”的协作方式。

> **实验性原型，不是可直接用于生产的无人值守开发系统。** 模拟流程、模型 API 连接测试、ZCode 会话兼容性检查和 Docker 测试是不同能力；其中任一通过，都不能替代其他环节的实际验收。

## 功能

- **组织与项目**：员工岗位、职责、直属领导、项目分配及启用状态；项目目前为新建的无外部依赖 Node 演示工作区，不导入真实业务仓库。
- **任务状态机**：规划、开发、独立测试、返工、审批与取消；持久化运行记录和审计，进程重启不会静默重放未完成任务。
- **员工模型**：读取本机显式配置的模型元数据，支持应用默认及员工独立模型／思考强度；保存选择不调用模型，不修改上游默认模型。
- **技能库**：经验先形成草稿，经人工审核后发布不可变版本，再显式分配给员工；技能数量无业务上限，单次知识注入有 24 KiB 限额。
- **执行与治理**：独立 API 测试、实验性 ZCode 原生会话适配器、受限 Docker 测试、只读本机健康探针。合并、推送、发布和部署执行器保持关闭。

## 当前能力边界

| 能力 | 当前范围 |
|---|---|
| 模拟协作流程 | 确定性演练，不调用模型或 Docker，不执行生成的代码；不能作为真实验收证据 |
| 独立模型 API 测试 | 显式确认后发送固定短提示；支持已核查的协议映射，不等于 ZCode 工具链通过 |
| ZCode 原生会话 | 实验性 Windows `app-server --stdio` 适配；需要匹配的安装版协议与本机配置，真实读写仍须单独验收 |
| Docker 测试 | 固定 Node 入口、无网络、非 root、只读根目录与工作区、资源限制和精确清理；不自动拉镜像 |
| 审批与运维 | 只有已登录的人类账号可记录批准；健康探针仅限明确登记的本机服务，不自动修复或发布 |

ZCode 适配器兼容性依赖安装版本。普通个人 API-key 模型、账户登录型模型、桌面专属插件和官方 MCP 认证具有不同边界，不能假定全部支持。当前公开快照仍需进一步完善原生工具事件解析、回合关联、员工检查界面和端到端执行验收；**测试通过不表示已完成生产安全审计或所有真实工具测试**。

## 环境要求

- Node.js **24.15.0 或更新版本**，使用内置 `node:sqlite`。
- npm；依赖版本固定在 `package.json` 和 `package-lock.json`。
- Web：React 19、Vite 7、TypeScript。
- 可选：Windows 上的 ZCode 桌面安装、Docker Desktop／Linux 容器引擎。其他系统可评估模拟功能；原生 ZCode 文件保护当前仅支持 Windows。

## 快速开始

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm start
```

打开 [http://127.0.0.1:3180](http://127.0.0.1:3180)。首次访问创建本机管理员，密码至少 12 个字符；没有默认账号或密码，初始化后注册入口关闭。

默认仅监听回环地址。请勿通过端口转发或反向代理直接暴露公网；当前版本没有公网部署承诺。

前端开发：

```bash
npm run web:dev
```

Vite 开发页为 [http://127.0.0.1:5180](http://127.0.0.1:5180)，API 代理到本机管理服务。Windows 也可使用 `start.ps1` 启动，它从 PATH 查找 Node。

## 本机配置

`config/example.json` 是不含凭据的示例。需要自定义时复制为 `config/local.json`，后者已被 Git 忽略。公开版本默认关闭真实执行意图；即使显式启用，也仍需当前模型、会话与 Docker 的实际检查证据。

| 设置 | 用途 |
|---|---|
| `AI_COMPANY_PORT` | 本机 HTTP 端口，默认 3180 |
| `AI_COMPANY_DATA_DIR` | 独立实例的数据目录，默认项目下 `data/` |
| `ZCODE_INSTALL_DIR` | ZCode 安装目录；也可在本机 JSON 中明确设置 `zcode.electronPath` 和 `zcode.cliPath` |
| `ZCODE_PERSONAL_PROVIDER_CONFIG_FILE` | 已有个人模型配置文件位置；只供本机读取，不提交其内容 |
| `config/local.json` 的 `docker.executable` | Docker 可执行文件路径；默认从 PATH 查找 `docker` |

`.env.example` 仅是环境变量参考；应用不会自动加载 `.env`，请由启动环境设置这些变量。

模型凭据由用户自行在 ZCode 中管理。不要把 API Key、登录令牌、SSH 私钥、云端或生产凭据放进本仓库。模型目录只是安全元数据投影，不展示凭据或原始配置。

### Docker 前提

需要自行安装并启动 Linux 容器引擎，在明确授权的网络环境中准备测试镜像：

```bash
docker pull node:24-alpine
```

应用检查只使用本地已有镜像，执行时固定不可变镜像 ID，并使用 `--pull never`。模型成功返回内容不等于容器测试通过。

### ZCode 前提

在 `config/local.json` 中配置本机安装路径，按需显式设置 `realExecutionEnabled: true` 和 `zcode.enabled: true`。页面“检查 ZCode 连接”可能消耗现有模型额度，检查时使用新建演示目录。

- 保留现有用户环境与扩展发现机制，但不承诺所有插件可用。
- 运行期间短时保护既有配置文件，避免原生加载器改写；请勿同时保存 ZCode 模型配置。
- 不接管用户现有聊天，不静默回退模型，不伪造账户认证成功。
- 这是**当前用户权限的受控进程，不是 OS 沙箱**。Docker 仅隔离测试代码，不隔离 ZCode 宿主进程。

## 验证

```bash
npm run typecheck
npm test
npm run build
```

测试涵盖认证／CSRF、任务状态机、审批约束、模型与员工配置、技能版本、文件路径与阶段校验、RPC 传输、配置只读保护以及 Docker 参数和清理。涉及网络和执行器的多数测试使用合成数据或 mock；真实模型、插件与容器需要在使用者环境另行验证。

```text

```

## 数据与安全

运行产生的账号、会话、任务、日志、技能与工作区都位于本机数据目录，**不属于公开源码**。本仓库不包含本机数据库、历史备份、真实项目验收记录、私有路径、配置副本或凭据。发布边界见 [公开源码检查说明](docs/publication.md)，安全限制见 [SECURITY.md](SECURITY.md)。

技能是可审核的知识文本，不是执行插件，也不训练模型权重。模拟经验永久标为仅演练可用，人工发布不能把模拟结果转换为真实生产验证。
